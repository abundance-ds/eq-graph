# Harmonization and validation record

## Result summary

The harmonized guide keeps the paper as the main record and adds a paper-local component only to prevent a false paper-level statement. It uses purpose-based, repeatable study families and exact method paths. It separates respondent, referent, reporting perspective, target population, and decision context. It also separates instrument identity, role, administration, outcome derivation, product states, evidence lineage, and attributed meaning.

The main resolutions are these:

- Health-state valuation and value-set development are separate families.
- Translation and cultural adaptation are separate families and can occur together.
- Broad method work is assigned to a precise family and exact method purpose. There is no general `methods study` family.
- Protocol publication, planned component, protocol product, and protocol use have strict separate roles.
- Paper-level `mixed status` and broad assessment class are derived, not stored.
- Product development, evidence, governance, access, recommendation, use, effect, and implementation are independent.
- Evidence overlap uses source-backed relation states and evidence basis, not a numeric confidence score.
- Review search and screening stay in the paper-local review component.
- Extraction uses a separate conflict pass, flow arithmetic, and repeated-fact comparison.

All 40 paper applications fit without a new forced family. All 27 questions and all 14 probes have a supported path. Remaining issues are source conflicts, transfer limits, causal ambiguity, and corpus limits, not missing core concepts.

## Material decisions, evidence, and consequences

| Decision | Paper or question evidence | Query or interpretation consequence |
|---|---|---|
| Keep components only when they prevent a false statement. | The Danish and Chinese value-set papers use distinct cTTO and DCE samples. The EQ-TIPS protocol has planned waves with different tasks and material availability. Q5 and Q9 require these paths. | A query can attach sample, task, method, status, and product to the correct component without creating a component for each analysis. |
| Split health-state valuation from value-set development. | The DCE-with-duration and anchoring papers study valuation methods and model scales. They do not all release an operational value set. Q10, Q14, and probe 1 require the split. | A value-set query does not retrieve every valuation experiment. A method query can still retrieve valuation work through task and purpose. |
| Split translation from cultural adaptation. | The Modern Standard Arabic work changes language. The Singapore English work changes locale wording within English. Q4, Q20, and probe 3 require both. | Users can filter cross-language translation, same-language localization, or papers that do both. |
| Use a narrow preference-method family and exact method purpose. | DCE with duration, OPUF, anchoring, and task comparisons have different targets. The uncertainty paper is conceptual guidance, and EQ-DAPHNIE quality is survey-method work. | A broad `methods study` result does not mix preference methods, survey quality, and conceptual guidance. Exact paths remain searchable. |
| Do not use protocol as a family. | The EQ-TIPS paper reports planned work and provides wave-1 conduct materials. EQ-DAPHNIE reports completed operating rounds and future expansion. Probe 9 exposes the false match. | A protocol-purpose query returns planned research. A product query can return reusable protocol materials. An infrastructure query does not gain a protocol tag merely from governed conduct. |
| Derive paper `mixed status`. | The oncology pilot has reported 3L pilot use and planned 5L work. The PTO and EQ-TIPS papers combine pilot evidence with planned main work. | Users can ask for papers with mixed component statuses without hiding which component is planned or complete. |
| Derive assessment class from exact target and purpose. | Bot checks, preference-order tests, value-set prediction, responsiveness, and workflow outcomes are distinct. Candidate 3's broad parent prevents confusion but duplicates facts when the exact path is present. | A user can group assessments when needed. Extraction stores one exact statement and avoids inconsistent parent and child tags. |
| Keep evidence and person roles separate. | Adults value a hypothetical child's health; experts review a toddler instrument; caregivers report on a child; reviews use publications as evidence. Q6 and probe 4 require the roles. | A respondent query does not confuse adults, children, experts, proxies, referents, and intended users. |
| Keep administration axes independent. | The online versus face-to-face cTTO paper changes panel source, contact, support, tutorial, feedback, and quality review together. Paper responses can later enter a digital system. | Queries can state the actual administration package and do not infer self-completion or a causal mode effect from one label. |
| Keep task form separate from inferential purpose, anchor, and time form. | DCE with duration, ordinary DCE, cTTO, PTO, EQ VAS, immediate-death tasks, and zero-duration anchors answer different questions. Probes 1 and 8 require this. | A task-name search stays precise. A DCE used to test instrument structure does not become value-set development. An EQ VAS result does not become a QALY-ready utility without the needed route. |
| Use independent product state dimensions. | EQ-DAPHNIE is operating but restricted. Arabic and Singapore language versions have governance and comprehension evidence but different later evidence needs. P-PROM ROCK is co-designed and mock-tested but not in routine care. | Product queries can ask separately about completion, evidence, approval, access, recommendation, use, effect, and implementation. No generic `tested` or `established` label overclaims status. |
| Represent overlap with source-backed relation states, not confidence scores. | Trinidad and Tobago norms reuse three sources with possible overlap. DCE-with-duration can use an independent cTTO benchmark. EQ-DAPHNIE papers reuse the same infrastructure. Q19, Q25, and probe 12 require component scope. | Users can distinguish same, partial, independent, possible, and unclear evidence. The record does not create a false paper-wide independence claim or a subjective numeric score. |
| Keep review search and screening in a paper-local review component. | The two reviews report sources, dates, eligibility, counts, screening, duplicate handling, and synthesis. Q8, Q9, and Q12 use these facts. | Review methods remain available with the paper. Detailed search syntax can stay in the source unless it affects a conflict or query. No extra evidence-synthesis layer is required for these 40 papers. |
| Add a mandatory conflict-focused extraction pass, not mandatory fields. | The candidates detected disjoint conflicts: 889 versus 496 plus 397, 236 versus 275 negative states, reversed DIF reference roles, and 0.600 versus 0.446 online range. Probe 13 requires all forms. | The ontology can support conflict records, and the workflow now improves the chance that extraction finds them. Competing statements and locations remain visible. |
| Keep outcomes and derivation paths explicit. | The dialysis mapping paper links observed response, mapped response or utility, QALY, and ICER. Level sum score, EQ VAS, utility, DALY, and cost also differ across the corpus. Q12 and probe 7 require the chain. | A user does not confuse a response, score, utility, QALY, burden estimate, or decision result. |
| Separate finding, interpretation, limitation, implication, use, effect, future work, and extractor inference. | The quality-control and P-PROM papers state findings, explanations, limits, expected implications, and future tests. They do not document all proposed effects. Q15 to Q18 and probes 10 and 11 require attribution. | The record does not convert author expectations into observed impact or extractor notes into author conclusions. |
| Use controlled, repeated, related, and narrative detail by function. | Exact instrument versions, methods, and outcomes recur and affect filters. Rationale, local frameworks, and competing explanations are paper-specific. | The guide stays concise and queryable without turning every named fact into a class or mandatory slot. |

## Rejected or derived distinctions

| Distinction | Disposition | Reason and effect |
|---|---|---|
| One exclusive study family | Rejected | The Singapore paper needs cultural adaptation, instrument development, and measurement-property work. Repeatable purpose tags preserve all material purposes. |
| Combined valuation and value-set family | Rejected | It produces false value-set matches for method and anchoring work. |
| Combined translation and cultural adaptation family | Rejected | It hides the Modern Standard Arabic versus Singapore English distinction. |
| General `methods study` family | Rejected | Exact method purpose plus preference-method, survey-method, or guidance family gives a more useful result. |
| Protocol family | Rejected | It confuses planned research, a conduct product, method use, and operating infrastructure. |
| Paper `mixed status` | Derived | Component statuses contain the evidence and identify the affected work. |
| Stored assessment class | Derived | Exact method purpose, target, property, or quality indicator supports the same grouping without duplicate extraction. |
| One product maturity ladder | Rejected | A product can be complete but restricted, approved but not psychometrically tested, or mock-tested but not implemented. |
| Bare `tested`, `validated`, `established`, or `final` state | Rejected | These labels do not identify evidence, scope, governance, access, or use. |
| Paper-level independent-evidence flag | Rejected | Independence can differ by component and comparison. |
| Numeric evidence-overlap confidence | Rejected for this corpus | The papers support qualitative source-backed states, but not a reproducible numeric calculation. |
| Universal cross-version response-level equivalence | Rejected | Response-label provenance can change mapped results even when ordinal levels appear aligned. |
| Correlation as agreement or interchangeability | Rejected | The mapping, EQ-HWB-S, and proxy papers show that high association does not establish agreement or replacement. |
| General feasibility as measurement property or implementation family | Rejected | Task feasibility, psychometric missingness, and workflow feasibility have different targets and effects. |
| Every alternative model as a product | Rejected | A model output is an analysis derivative unless the paper identifies a reusable output. |
| Universal quality, reliability, agreement, or success threshold | Rejected | The 40 papers use purpose- and level-specific rules. Preserve the source rule and consequence. |
| Corpus gap | Derived after extraction | A corpus gap needs explicit filters, corpus version, and date. It is not an author finding. |
| Corpus trend over time | Derived with linked source dates | Semantic records provide families, methods, products, and update relations. The JATS layer supplies dates. |
